# Diabeto Architecture Specification

## 1. High-Level Architecture
Diabeto is structured as a **FastAPI Modular Monolith** coupled with Supabase PostgreSQL and a Next.js web application.

```mermaid
graph TD
    Senior[Senior Patient] -->|WhatsApp Audio/Text| Webhook[WhatsApp Webhook Handler]
    Webhook -->|STT via Sarvam AI| Ingestion[Ingestion Module]
    Ingestion -->|Validate 20-600 mg/dL| EventStore[(PostgreSQL Event Store)]
    EventStore -->|Transactional Outbox| JobsQueue[(Postgres Jobs SKIP LOCKED)]
    
    Ingestion -->|Sync Evaluation| RiskEngine[Deterministic Risk Engine]
    RiskEngine -->|Breach Detected| Escalation[Escalation State Machine]
    Escalation -->|Pre-Approved Template| WhatsAppOut[WhatsApp Outbox Dispatcher]
    
    JobsQueue -->|Async Processing| TrendModule[Trend & Analytical Rollups]
    TrendModule --> ContextBuilder[Deterministic Context Builder]
    ContextBuilder --> LLMGateway[Groq / Gemini LLM Gateway]
    LLMGateway --> Guardrails[Number-Fidelity Validator]
    Guardrails --> ApprovalQueue[Coach / Doctor Review Queue]
    ApprovalQueue -->|Human Approval| WhatsAppOut
    
    EventStore --> ClinicianWeb[Next.js Clinician & Coach Portals]
```

## 2. Component Separation & Responsibilities
- **API & Channels (`apps/api/app/channels/`):** Webhook intake, cryptographic signature verification, Twilio/Meta payload parsing.
- **Ingestion (`apps/api/app/modules/ingestion/`):** Range validation (20-600 mg/dL), echo confirmation, immutable event write.
- **Risk Engine (`apps/api/app/modules/risk/`):** Synchronous deterministic threshold evaluator (<70, <80, >180, >=250 mg/dL).
- **Adherence (`apps/api/app/modules/adherence/`):** Medication scheduling and dose confirmation.
- **AI Gateway & Guardrails (`apps/api/app/modules/ai_gateway/`):** PII scrubbing, context assembly, JSON schema output enforcement, and number-fidelity checks.
- **Approvals (`apps/api/app/modules/approvals/`):** Human-in-the-loop review queue for coaches and clinicians.
- **Durable Jobs (`apps/api/app/core/jobs.py`):** Transactional outbox using PostgreSQL `FOR UPDATE SKIP LOCKED`.

## 3. Reliability & Safety Rules
1. Zero AI dependency on emergency paths.
2. Every number generated by LLM must strictly exist in the evidence payload.
3. Idempotent webhook processing using provider message IDs (`source_msg_id`).

## 4. Frontend & Mobile PWA Layer
- **PWA Shell (`apps/web/public/`):** Standalone web app manifest (`manifest.json`), service worker cache (`sw.js`), and offline fallback for unstable 4G networks in India.
- **Elder Navigation (`apps/web/src/components/PatientBottomNav.tsx`, `TodayScreen.tsx`):** 4 primary navigation tabs (Today, Log, Ask, Me), persistent 56px floating emergency SOS button, 3-mode text scaling (18px/22px/26px), and Noto Sans Devanagari regional typography.
- **Clinician Directory & Chart Workflow (`apps/web/src/components/ClinicianPortal.tsx`):** 2-stage hierarchical navigation separating the high-level patient triage directory (`viewMode: 'roster'`) from the focused, dedicated patient clinical chart (`viewMode: 'chart'`) with breadcrumbs (`Patients → [Name]`), quick switcher, and zero visual clutter.
